# General Software Principles

## Documentation

- Please be as judicious while documenting code (docstrings, comments, etc.). The primary objective is to write code that is self-explanatory using clear variable and function names, and intuitive design. Documentation should only be used to clarify complex logic or provide necessary context that cannot be easily inferred from the code itself
- Docstrings and comments when required must be as succinct as possible. Don't write paragraphs of documentation unless absolutely warranted. Apart from a few exceptions (highly technical code, core logic, etc), most things can and should be explained in a sentence or two.
- Avoid roundabout explanations and unnecessary details in documentation

## Working with Git
- Never commit code unless explicitly asked to
- Never push commits unless explicitly asked to
- Never put up PRs unless explicitly asked to

## Opening PRs

- When asked to create PRs, please ensure that the PR title is clear and concise
- PR descriptions must contain details of the PR but avoid extremely verbose descriptions. Explain things wherever necessary but follow the same principles as mentioned in the documentation section and don't be redundant
